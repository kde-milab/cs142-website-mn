ICSI301 Төсөл 6: Аппсервер ба өгөгдлийн сан

Энэ төсөлд та өгөгдлийн сангийн системийг эхлүүлж, 5-р төсөлд хийсэн өөрийн фото зураг хуваалцдаг веб аппыг харагдацад (view) моделийг өгөгдлийн сангаас авдаг байхаар хөгжүүлнэ. Энэ нь танд өөрийн аппыг албан ёсоор full stack программм болгох боломжийг олгоно.

Энэ болон бусад хичээлийн даалгаврын хувьд бид веб программын бүх гурван шатлалууд болох хөтөч, веб сервер, өгөгдлийн санг таны өөрийн машин дээр ажиллуулна.

MongoDB өгөгдлийн санг эхлүүлэх

Суулгах зааварт заасны дагуу өөрийн орчинд MongoDB ажиллаж байгаа эсэхийг шалгаарай. Өгөгдлийн сан хаагдах хүртэл mongod комманд буцаагдахгүй тул та үүнийг тусдаа цонхонд эсвэл арын процесс болгон ажиллуулахыг хүсэх болно. (Жишээ нь: mongod (args) & Linux/MacOS дээр).

MongoDB серверийг ажиллуулсны дараа та дараах коммандыг ажиллуулж зургийн программын өгөгдлийг ажиллуулж болно: 

node loadDatabase.js
Энэ программ нь өмнөх төслүүдийн (жишээ нь: src/modelData/photoApp.js) гэх мэт загварын өгөгдлийг өгөгдлийн санд оруулдаг. Манай аппд ямар нэгэн зүйл нэмэх, шинэчлэх ямар ч шаардлага байхгүй тул та loadDatabase.js файлыг нэг удаа ажиллуулахад л хангалттай. программм нь өгөгдлийг оруулахаас өмнө өгөгдлийн санд байгаа бүх зүйлийг устгадаг тул олон удаа ажиллуулахад аюулгүй.

Бид MongooseJS Object Definition Language (ODL) хэлийг ашиглан MongoDB өгөгдлийн санд photo app өгөгдлийг хадгалах schema тодорхойлно. Схемийн тодорхойлсон файлууд schemaхавтаст байгаа:

  • schema/user.js - Хэрэглэгч бүрийг дүрсэлсэн объектуудыг агуулсан Users цуглуулгыг тодорхойлно.
  • schema/photo.js - Зураг бүрийг дүрсэлсэн объектуудыг агуулсан Photos цуглуулгыг тодорхойлно. Энэ нь мөн зураг дээр бичсэн сэтгэгдлийг хадгалахад ашигладаг объектуудыг тодорхойлдог.
  • schema/schemaInfo.js - Схемийн хувилбарыг тодорхойлсон объектыг агуулсан SchemaInfo цуглуулгыг тодорхойлно.
Эдгээр файлыг өгөгдлийн сан үүсгэхэд ашигладаг loadDatabase.js скрипт болон өгөгдлийн санд хандахад ашигладаг webServer.js файлууд хоёулаа дуудаж хэрэглэдэг. Тайлбар: Өгөгдлийн санд хадгалагдсан объектын схем нь өмнөх даалгаварт ашигласан icsi301models JavaScript объектуудтай төстэй боловч бага зэргийн ялгаатай болно.

Node.js веб серверийг эхлүүлэх

Өгөгдлийн санг ажиллуулсны дараа веб серверээ эхлүүлэх хэрэгтэй болно. Үүнийг өмнөх даалгавартай ижил командаар хийж болно (жишээ нь: node webServer.js эсвэл npm start). Веб серверээ project6 хавтас дотроос дараах командаар асаана: 

node webServer.js

Төсөл 5-ын адил сервер нь dist хавтсын файлаар үйлчилдэг тул аппын багцыг (bundle) үүсгэх хэрэгтэй. project6 хавтас дотроос командын мөрийн өөр цонхонд: 

npm run build:w
командыг ажиллуулбал та аппын кодоо өөрчлөх бүрт багц автоматаар шинэчлэгдэнэ.

Хэрэв та дээрх командыг ашигладаг бол серверийн кодыг өөрчлөх болгондоо веб серверээ дахин эхлүүлэхээ мартуузай. Та мөн серверийн кодын өөрчлөлтийг ажиглаж , веб серверийг автоматаар дахин эхлүүлэх Node.js-ийн --watch горимыг ашиглаж болно: 

npm run dev
Энэ скрипт нь node --watch webServer.js командыг ажиллуулж, webServer.js болон түүний импортолсон файлуудыг (жишээ нь, schema хавтас доторх файлууд) хянана.

Төсөл 6-ийн шинэ файлуудаар Photo Share программаа шинэчилж, өгөгдлийн сан болон веб серверийг ажиллуулсны дараа даалгавраа үргэлжлүүлэхийн өмнө программ ажиллаж байгаа эсэхийг шалгана уу.

Өгөгдлийн сан ашигладаг веб сервер болгон хөрвүүлэх (40 оноо)

Энэ төсөлд бидний танд өгөх webServer.js Төсөл 5-ын webServer.js файлтай адил бөгөөд программын модель татах замууд нь өгөгдлийн сангаас авахгүй, нөгөө шидэт icsi301models моделийг ашигладаг. Таны даалгавар бол MongoDB өгөгдлийн санг ашиглан бүх замыг хөрвүүлэх юм. Таны кодод icsi301models-д хандах эрх байх ёсгүй бөгөөд таны программ дараах мөргүйгээр ажиллах ёстой: 

import icsi301models from './src/modelData/photoApp.js';
webServer.js доторх console.log нь веб хөтөч дээр биш терминал дээр хэвлэгдэх болохыг анхаарна уу.

Web Server API

Төсөл 5-ын нэгэн адил веб сервер нь тодорхой URL-ууд руу HTTP GET хүсэлтийн хариуд JSON кодлогдсон модель өгөгдлийг буцаана. Бид ямар URL-уудыг дэмжих, юуг буцаах талаар дараах тодорхойлолтыг өгөв. Таны веб сервер дараах модель татах API-г дэмжих ёстой:

  • /test - Өгөгдлийн сангийн схемийн мэдээлэл (/test/info) болон объектын тоог (/test/counts) буцаана. Энэхүү интерфэйс нь туршилтад зориулагдсан бөгөөд жишээ болгон өгөгдлийн сангаас өгөгдөл авах программыг харуулж байгаа юм. Үүнийг өөрчлөх шаардлагагүй.
  • /user/list - Аппын хажуу талын жагсаалтад тохирох хэрэглэгчдийн модель жагсаалтыг буцаана. Олон тооны хэрэглэгчийг хүлээж авах тул энэ API нь зөвхөн хажуу талын жагсаалтад шаардлагатай хэрэглэгчийн шинж чанаруудыг агуулсан массивыг буцаана (_id, first_name, last_name). Энэ нь өгсөн код дахь icsi301models.userListModel() дуудлагыг орлох учиртай юм.
  • /user/:id - id параметрт тохирох _id-тэй хэрэглэгчийн дэлгэрэнгүй мэдээллийг буцаана. Энэ нь хэрэглэгчийн талаарх дэлгэрэнгүй мэдээллийг (_id, first_name, last_name, location, description, occupation) буцааж өгөх ба icsi301models.userModel() дуудлагыг солих ёстой. Хэрэв хэрэглэгчийн id-ээс өөр зүйл өгсөн бол хариу нь HTTP статус 400 ба мэдээллийн зурвас байх ёстой.
  • /photosOfUser/:id - id параметрт тохирох _id-тэй хэрэглэгчийн зургийг буцаана. Энэ дуудлага нь хэрэглэгчийн бүх зураг, мөн зураг дээрх сэтгэгдлүүд зэрэг зураг үзэхэд шаардлагатай бүх өгөгдлийг өгдөг байна. Зургийн шинж чанарууд нь (_id, user_id, comments, file_name, date_time) байх ба тайлбарын массивын элементүүд (comment, date_time, _id, user) байх ёстой бөгөөд зөвхөн хамгийн бага хэрэглэгч-ийн объектын мэдээлэл (_id, first_name, last_name) байх ёстой. Энэ нь icsi301models.photoOfUserModel() дуудлагыг орлоно. Хэрэв хэрэглэгчийн id-ээс өөр зүйл өгсөн бол хариу нь HTTP статус 400 ба мэдээллийн зурвас байх ёстой. Энэ API-г хийхэд өгөгдлийн сан дахь олон өөр объектоос угсарч гаргасан модель байх ёстойг анхаарна уу. Mongoose-ээс өгсөн өгөгдлийн сангийн асинхрон интерфэйс нь эдгээр олон объектыг татах үйлдлийг нэгэн зэрэг хийх боломжтой байдаг. Таны код цуварсан байдлаар өгөгдлийг татах ёсгүй. Mongoose-ийн хайлтууд Promise буцаадаг бөгөөд ЖаваСкриптийн Promise.all нь зэрэгцээ таталтыг удирдахад тустай. Жишээг webServer.js доторх /test/counts-аас харна уу.

Таны веб сервер зохих API-д нийцэж байгаа эсэхийг шалгахын тулд test дэд төслийг өгсөн байгаа. Илгээхээсээ өмнө тестэд байгаа бүх шалгалтыг давсан эсэхийг шалгана уу. Дэлгэрэнгүйг доорх Тест хэсгээс үзнэ үү.

Таны GET хүсэлтүүд нь icsi301models функцүүдийн буцаадаг зүйлтэй яг ижил зүйлийг буцаадаггүй боловч харагдац бүрийн моделийг нэг fetchModel дуудлагаар харуулахын тулд таны аппд шаардлагатай мэдээллийг буцаах шаардлагатай. UI-ийн хэрэгцээг хангахын тулд, өөрийн хариултыг бий болгохын тулд өгөгдлийн сангаас ирж буй объектуудыг дэд тохиргоо болон/эсвэл нэмэгдүүлэх шаардлагатай болно. Энэ даалгаврын хувьд өгөгдлийн сангийн схемийг ямар нэгэн байдлаар өөрчлөх хэрэггүй.

*ЧУХАЛ!*

Эдгээр Express API-ыг хэрэгжүүлэхийн тулд хоёр өөр "модель" объекттой харилцах шаардлагатай. Mongoose систем нь MongoDB-д хадгалагдсан объектуудаас models-уудыг буцаадаг бол хүсэлт нь өөрөө PhotoShare App-ын харагдацад шаардлагатай моделийг буцаах ёстой. Харамсалтай нь, Mongoose модель нь өгөгдлийн сангийн схемээр, front-end модель нь UI-ийн харагдацын шаардлагаар тодорхойлогддог тул хоорондоо төгс нийцдэггүй. API нь хариултыг зөв өгөхийн тулд өгөгдлийн сангаас буцаасан Mongoose моделиос front-end-д шаардлагатай загварыг угсарч гаргах шаардлагатай болдог.

Mongoose-ийн буцаасан моделиуд нь JavaScript объектууд боловч тэдгээрт тусгай боловсруулалт хийгдсэн тул зарлагдсан схемд тохирохгүй аливаа өөрчлөлтийг хаях тул энэ боловсруулалтыг хийхдээ болгоомжтой байх хэрэгтэй. Энэ нь Mongoose загварыг front-end-д шаардлагатай шинж чанаруудтай болгохын тулд зүгээр л шинэчлэх нь санаснаар болохгүй гэсэн үг юм.

Энэ асуудлыг шийдэх нэг арга бол шинэ JavaScript объект үүсгэж, Mongoose схемээс авсан өгөгдлийг API-д шаардлагатай талбаруудаар дүүргэх явдал юм. API-д заасан JavaScript өгөгдлийн бүтцийг ийм байдлаар бүтээж, HTTP хариултанд буцааж өгч болно. API загвар нь Mongoose загвартай нягт таарч байгаа REST эндпойнтын хувьд өөр нэг арга бол Mongoose проекцын операторыг (сонгож) ашиглан хайлт нь зөвхөн API-ийн заасан загварын талбаруудыг буцаана. Хэсэг нь эдгээр техникийг илүү нарийвчлан авч үзэх болно.

Mongoose болон API загварууд ижил байсан ч проекц хийхгүйгээр Mongoose загварыг буцаах нь программчлалын муу практик юм. Ирээдүйн төслүүд өгөгдлийн сангийн схемийг өргөтгөх болно (жишээ нь, хэрэглэгчийн загварт нууц үг нэмэх), гэхдээ бид эдгээр шинж чанарыг API загварт оруулахыг хүсэхгүй.

Даалгавар 2: Өөрийн программыг axios ашигладаг болгох (10 оноо)

Бид REST API-г илүү ашиглах дараагийн даалгаварт бэлтгэхийн тулд веб серверээс моделиудыг татахын тулд өөрийн fetchModel функцээс арай илүү axios ашиглахаар зургийн программаа өөрчилнө. Axios бол өгөгдөл татах боломжтой npm багцуудын нэг юм. Энэ нь манай fetchModel функцээс илүү хурдан бөгөөд илүү олон функцтэй бөгөөд бид үүнийг цаашид хүсэлт явуулахад ашиглана. Энэ асуудлыг дуусгасны дараа таны зургийн апп fetchModel функцийн (src/lib/fetchModelData.js) тодорхойлолтгүйгээр ажиллах ёстой. fetchModel функцийн тодорхойлолтыг арилгахын өмнө болон дараа нь таны программын ажиллагаа яг ижил байх ёстой -- энэ шилжүүлгийг хийх явцад ямар нэгэн зүйл эвдэхгүй байгаа эсэхийг шалгаарай.

Ялангуяа src/photoShare.jsx эсвэл src/components доторх бусад компонент дотор fetchModel хэрэглэсэн газар бүрд үүнийг axios.get болгох хэрэгтэй. Дэлгэрэнгүй мэдээллийг axios баримтаас танилцах боломжтой.

axios руу шилжих зарим зөвлөмжийг энд оруулав:

  • axios ашиглан өгөгдөл татаж авах аливаа компонент дотор дараах байдлаар импортлохоо мартуузай: 

     import axios from 'axios';

  • axios.get нь fetchModel шиг Promise буцаадаг болохыг анхаарна уу. Бид .then болон .catch тус тус ашиглан амжилт ба алдаа зохицуулагчийг хавсаргаж болно. Аливаа хүсэлтийн амжилт болон алдааны тохиолдлуудыг хоёуланг нь зохицуулах нь чухал юм. axios.get -д хавсаргахдаа fetchModel-аас зохицуулагчийн логикийг өөрчлөх шаардлагагүй.

Тест

Тестийн хувьд бид таны программын зөвхөн back-end test өгсөн болно. Тест нь Node.js тест бичихэд зориулагдсан түгээмэл фрэймвөрк болох Mochaашигладаг. Туршилтын орчныг тохируулахын тулд test гэсэн хавтас дотроос Mocha болон холбогдох бүх модулийг npm install командаар татаж авна. Үүнийг хийсний дараа дараах командаар тестийг ажиллуулж болно: npm test.

npm test Mocha хэлээр бичсэн, жишээ нь, describe() болон it() функцүүдийг ашиглан бичсэн тестүүдийг ажиллуулдаг. Тест нь таны веб серверийн гурван URL-ийг (/user/list, /user/ID, /photosOfUser/ID) шалгана. Ингэхдээ test/serverApiTest.js файлыг ажиллуулдаг. Таны API функцүүд шаардлагад нийцэж байгааг шалгахдаа илгээхээсээ өмнө бүх туршилтыг давж байгаа эсэхийг харж шалгана уу. Таны төслийн үнэлгээний нэг хэсэг нь эдгээр шалгалтын хэд нь тэнцсэнээс хамаарна.

Нэмэлт оноо (10 оноо)

Таны PhotoShare App-ын маркетингийн хэлтэс нь программыг нийгмийн сүлжээнд илүү ээлтэй болгохын тулд "жижиг" засвар хийсэн. Өөрчлөлт нь:

  • Хэрэглэгчдийн жагсаалтыг агуулсан хажуу талын жагсаалтын талбарт хэрэглэгчийн нэр бүрийн хажууд тоолох хоёр count bubbles байх ёстой. Эхний тооны бөмбөлөг (ногоон өнгөтэй) нь хэрэглэгчийн системд байгаа зургийн тоо байх ёстой. Хоёр дахь бөмбөлөг (улаан өнгөтэй) нь хэрэглэгчийн бичсэн сэтгэгдлүүдийн тоо байх ёстой.
  • Хэрэглэгчийн сэтгэгдлийг тоолох bubble дээр дарснаар хэрэглэгчийн бүх сэтгэгдлийг харуулдаг шинэ харах бүрэлдэхүүн хэсэг рүү очно. Хэрэглэгчийн сэтгэгдэл бүрийн хувьд сэтгэгдэл бичсэн зургийн жижиг өнгөц зураг болон сэтгэгдлийн текстийг харуулах ёстой. Сэтгэгдэл эсвэл зураг дээр дарснаар тухайн зураг болон түүний бүх тайлбарыг агуулсан зургийн дэлгэрэнгүй харагдац руу шилжих хэрэгтэй. Та 5-р төсөлд stepper нэмэлт кредитийг хэрэгжүүлсэн эсэхээс яг тодорхой харагдах байдал хамаарна.
  • Төслийн 5-ын дэвшилтэт функцийн туг идэвхжсэн тохиолдолд л энэ өөрчлөлт харагдах болно. Хэрэв та Төслийн 5-ын нэмэлт кредитийг хийгээгүй бол алхам алхамыг хийх шаардлагагүй, гэхдээ дээрх нэмэлт зээлийн функцийг асаах, унтраах боломжтой болгохын тулд дэвшилтэт функцийн туг удирдлагыг хэрэгжүүлэх шаардлагатай хэвээр байна.

Үүнийг хэрэгжүүлэхдээ та шинэ серверийн API дуудлагуудыг нэмэх эсвэл одоо байгаа дуудлагуудыг сайжруулах боломжтой. Хэрэв та үүнийг хийвэл шинэ функцээ шалгахын тулд Mocha тестийг (test/serverApiTest.js) шинэчлэх шаардлагатай. Хэрэв та шинэ API-үүдийг нэмбэл, бусад тестүүдэд ашигласан загварын дагуу шинэ describe() блокт оруулна уу. Бүртгүүлэхээсээ өмнө өгсөн тестүүд тэнцсэн хэвээр байгаа эсэхийг шалгаарай. Та Mongoose схемд шинэ шинж чанарууд нэмэх ёсгүй, гэхдээ та үүнийг илүү том өгөгдлийн багц дээр ажиллуулахын тулд шаардлагатай индексүүдийг нэмж болно.

Багш нар үнэлгээ өгөхийн тулд таны аппликейшн дээр (хэрэв байгаа бол) Нарийвчилсан функцүүдийн тохиргоог идэвхжүүлж, нэмэлт кредит хэсэгт үнэлгээ өгөх эсэхийг тодорхойлохын тулд UI тоолох bubbles хайж олно.

Загварын оноо (5 оноо)

Хэрэв таны даалгаврт MVC бүтцийг зөв зохион байгуулж хэрэгжүүлсэн бол энэ оноог олгоно. Нэмж дурдахад, таны код болон модулиуд нь цэвэр, уншигдахуйц байх ёстой бөгөөд таны апп нь гадаад төрх, харагдацын хувьд "боломжийн сайхан" байх ёстой.

Илгээхээсээ өмнө npm run lint ажиллуулахаа мартуузай. Линтер нь алдаа гаргахгүй байх ёстой.

Хүлээлгэн өгөх үр дүн
